`npm test` で全テストを流したところ、**失敗が 6 件**ありました（全 794 件中 788 件成功、93 スイート中 3 スイートで失敗）。

`npm test` は最初に、タイムゾーンを固定したテストを 8 回流します（`test-tz` と `test-tz-plugin`）。ここは全部通りました。失敗が出たのは、最後のタイムゾーン指定なしで回す jest です。このマシンは今 PDT（America/Los_Angeles）なので、その設定で動いています。

| ファイル | テスト | 期待値 → 実際の値 |
|---|---|---|
| `test/plugin/timezone.test.js:157` | Spring Forward 2012-03-11 02:00:00 | `03:00-04:00` → `04:00-04:00` |
| `test/plugin/timezone.test.js:168` | Spring Forward 2012-03-11 02:59:59 | `03:59:59` → `04:59:59` |
| `test/plugin/timezone.test.js:179` | Spring Forward 2012-03-11 03:00:00 | `03:00` → `04:00` |
| `test/plugin/timezone.test.js:218` | Fall Back 2012-11-04 02:00:00 | `02:00-05:00` → `01:00-05:00` |
| `test/plugin/dayOfYear.test.js:33` | DayOfYear set | `2015-01-04` → `2014-01-05` |
| `test/plugin/localizedFormat.test.js:31` | 角括弧内の文字を展開しない | `1970 l 1970` → `1969 l 1969` |

**原因はマシンのタイムゾーンとみられます。** `TZ=UTC` を付けて同じテストをもう一度流すと、794 件すべて通りました。どの失敗も UTC の日時をローカル時刻で解釈していて、PDT（UTC−7）だと 1 年前や 1 日前、あるいは 1 時間ずれた結果になります。ライブラリの退行ではなく、テストがローカルのタイムゾーンに依存している、という問題だと考えられます。

- カバレッジは行 100%、ブランチ 99.51% で、行 100% のしきい値は満たしています。
- 動かした環境は Node v24.21.0 です。

テストを特定のタイムゾーンに依存しないように直すか、`npm test` の最後の jest に `TZ=UTC` などを付けて固定するか、どちらか対応しましょうか？
